Macavation User Guide

How to use the operations portal for macadamia intake, production, stock, dispatch, quality, and administration.

About this page. This guide is a single readable overview (structure similar to the Tracker Academy user guide). The live app usually requires sign-in. Quick start

  1. Open the sign-in page and log in with the account your administrator provided (your organisation may include a client link with a cc code in the URL).
  2. Use the left sidebar to open a module. What you see depends on your role.
  3. Start from grid or board views to see batches, stock lines, or records; open row actions, toolbars, or cards to run checklists, job cards, and forms.
  4. Use toolbar actions such as Create, Release to production, Send to Dispatch, Export, and Refresh as your screen provides them.
  5. Use Help on a screen to open the contextual topic for that module in a new browser tab.
  6. Use Batch Journey when you know a batch identifier but not which module currently owns the work.

Navigation overview

The portal uses a sidebar plus top bar layout.

Sidebar sections (typical)

  • Dashboard — operational overview; may include Material Journey and Executive views.
  • Batch Journey — search batches across intake, production, QA, and dispatch.
  • CRM — contacts (NIS suppliers, kernel customers, oil and protein customers, ingredient suppliers, processors).
  • Kernel — Grower Intake, Kernel Production, Stock (Kernel), Kernel Dispatch.
  • Oil & Protein — Supplier Intake, Oil Production, Stock (Oil & Protein), Oil & Protein Dispatch.
  • Quality — Quality Assurance tests and records.
  • Business — Sales Forecasting, Financial Management (where enabled).
  • Document Management and Palladium Integration — documents and ERP sync status.
  • User Management — Users, Roles, Database Role Permissions, Role Features, Features.
  • System Administration — consolidated admin views (varies by deployment).
  • Test Management — test scenarios and data (non-production environments only).

Top bar and global actions

  • My Day — role-based tasks and shortcuts (dropdown and full page).
  • User menu and Sign out.
  • Dark mode and sidebar collapse (footer of the sidebar).
  • Data Import (Excel) may appear as a quick action from the dashboard area when enabled.

Core workflows

1) Kernel stream (grower to kernel dispatch)

  • Register and receive material in Grower Intake (receiving checklist, samples, batch tests as required).
  • Create or release kernel batches toward Kernel Production (job cards, production stages, silos).
  • Move finished kernel stock in Stock (Kernel); use Send to Dispatch toward sales baskets.
  • Complete Kernel Dispatch (basket, inspection, dispatch paperwork) using CRM kernel customers.

2) Oil and protein stream (supplier to oil dispatch)

  • Receive supplier material in Supplier Intake (receiver checklist, oil batches, tests).
  • Run Oil Production (raw batches in production, production sheets, finished goods).
  • Manage lots and finished oil/protein in Stock (Oil & Protein); send lines toward dispatch when released.
  • Complete Oil & Protein Dispatch with the same basket and inspection pattern as kernel dispatch.

3) Quality and compliance

  • Log tests in Quality Assurance; failed or conditional results may block the next step depending on configuration.
  • Keep CRM contacts accurate so intake and dispatch paperwork match real customers and suppliers.

4) Administration and integration

  • Maintain users, roles, permissions, and feature flags in User Management (restricted roles).
  • Use Palladium Integration for sync health; follow your runbook for manual sync.
  • Use Data Import (Excel) only with approved templates; fix spreadsheets using import logs rather than repeating bad files.

Operations modules

Most operational modules follow a similar rhythm: find the record (search, filters, board/table) → complete the required steps in order → export or hand off to the next stage. Exact buttons depend on your role and batch status.

Grower Intake Kernel Production Stock (Kernel) Kernel Dispatch Supplier Intake Oil Production Stock (Oil) Oil Dispatch Quality Assurance CRM

Grower Intake

  • Purpose: Kernel-side receiving: checklists, samples, linking batches before production.
  • Typical flow: Complete Receiving checklist → run enabled test/sample steps → Create kernel batch or release when rules allow → Release to production (silo selection if prompted).
  • Hand-off: Kernel Production receives released batches.

Kernel Production

  • Purpose: Factory execution: silos, job cards, production stages, batch summary and history.
  • Typical flow: Manage silos → open a batch → job card and stages in order → QA hand-offs per your rules → release toward stock when complete.
  • Hand-off: Stock (Kernel) and dispatch when product is finished and released.

Stock (Kernel) and Kernel Dispatch

  • Purpose: Warehouse truth for kernel lines; building and shipping customer baskets.
  • Typical flow: Filter by location/status → align counts with the floor → Send to Dispatch → complete dispatch forms only when the physical load matches the basket.

Supplier Intake and Oil Production

  • Purpose: Oil-side receiving and conversion to finished oil/protein records.
  • Typical flow: Receiver checklist (or Adjust stock) for new deliveries; capture manufactured date and best-before auto-calculates as +18 months. Add bag asks how many rows to create, copies first-row values, and sequences batch numbers automatically → batch tests as enabled → production sheets and raw batch processing on the oil grid.

Stock (Oil & Protein) and Oil Dispatch

  • Purpose: Lots, best-before, and despatch of oil/protein finished goods.
  • Typical flow: Maintain oil lots (including import where allowed) → send released lines to dispatch → inspection and paperwork before shipment.

Quality Assurance

  • Purpose: Record tests and evidence; outcomes may gate release.
  • Typical flow: Filter → New quality test or open a row → attach files if required → Export for audits.

CRM

  • Purpose: Master data for growers, customers, and suppliers used on intake and dispatch screens.
  • Typical flow: Choose the correct tab → filters → Add Contact or import from Excel without changing template headers.

Module status mindset

  • In progress: Checklists incomplete, tests pending, or production stages not finished — editing is usually allowed where the UI enables it.
  • Released / dispatched: Treat data as committed for operations; corrections follow your SOP (often stock or admin).
  • Read-only views: Job card view, production stages view, batch history — for verification, not editing.

Dashboards, journey, and exports

  • Dashboard — snapshot cards and links; refresh the browser if numbers look stale.
  • Material Journey / Executive — integrator or leadership views; use in-page refresh where provided.
  • Batch Journey — cross-module batch search; follow links into the owning module to complete work.
  • Exports — many grids offer Export for spreadsheets; Data Import runs the opposite direction with strict templates.

Roles and permissions

What you can open in the sidebar and which API operations succeed depend on roles, role permissions, and role features configured in User Management.

  • If a menu item is missing, your role may not include that feature, or a feature flag may be off.
  • If you see Access denied and a redirect to the dashboard, ask an administrator to review role assignment and permissions.
  • User Management grids are usually limited to administrators or managers.
  • Avoid shared logins; use password reset or admin-assisted recovery instead of sharing credentials.

Troubleshooting

  • Stale grids: Use the screen Refresh control if present, then reload the browser once.
  • Actions disabled: Earlier steps may be incomplete (for example receiving checklist before tests), or the batch may be in a read-only state.
  • Wrong quantities on dispatch: Fix stock or the basket in Stock Management; do not force dispatch paperwork to match incorrect inventory.
  • Import failures: Correct column mapping and template headers; read the import log.
  • Cannot access a section: Ask an administrator to verify role, role features, and database role permissions.
  • Login issues: Use your organisation’s password reset or contact support; ensure you use the correct client link if your site requires cc.
